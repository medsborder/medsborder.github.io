# Технічні обмеження

- HTML/CSS/vanilla JS, **без фреймворків і бандлерів**, якщо без них реально можна. Якщо потрібна збірка (sitemap, валідація даних, мінімізація, OG-картинки) — **у Docker**.
- `justfile`: serve, build, validate-data, sitemap, lint/check-links, test, preview, clean.
- Хостинг: **GitHub Pages** (base path для project pages і варіант custom domain; GitHub Actions для деплою).
- Вся логіка на клієнті; введені інгредієнти не передаються на наші сервери (їх немає).
- A11y (WCAG AA): клавіатура, ARIA combobox для autocomplete, контраст, `prefers-reduced-motion`, статус не лише кольором (іконка + текст).
- Швидке завантаження, дані ліниво (JSON), статичний контент працює без JS (progressive enhancement).

# Аналітика і згода (GDPR / ePrivacy / UK PECR)

Планується Google Tag Manager `GTM-WJMLCVGW`. Сніпет від мене:

```html
<script async src="https://www.googletagmanager.com/gtm.js?id=GTM-WJMLCVGW"></script>
<script>
  window.dataLayer = window.dataLayer || [];
  function gtag(){dataLayer.push(arguments);}
  gtag('js', new Date());
</script>
```

Він нестандартний (змішує gtm.js і gtag) — звір зі штатним GTM-сніпетом і запропонуй коректну інтеграцію.
Вимоги:
- Користувач може **прийняти або відхилити** аналітику. До явної згоди GTM/GA **не завантажується** і нічого не ставиться (або, за вибором: Consent Mode v2 з `default: denied` — обговори з плюсами/мінусами).
- Банер: «Прийняти» і «Відхилити» однакової помітності, без dark patterns, без попередньо відмічених опцій; згоду можна змінити або відкликати в будь-який час (посилання «Cookie settings» у футері). Вибір зберігається (з терміном дії) і не блокує користування сайтом.
- Банер двомовний, підлаштовується під тему, доступний з клавіатури.
- Сторінка Privacy/Cookie policy (EN/UK): що збирається, ким, навіщо, строки, права користувача, контакт. Розрізни аналітику й дані форми (інгредієнти/країни **не** надсилаємо в analytics як події/параметри — запропонуй, які події допустимі).
- Посилання на Google/ChatGPT передають введені інгредієнти третім сторонам — окреме коротке попередження.
- Запропонуй, чи потрібен CSP/`rel="noopener noreferrer"` і як ці вимоги узгоджуються з GitHub Pages.
- Назви юрисдикції, що вплинули на рішення (GDPR, UK GDPR/PECR, ePrivacy), і що потрібно від мене як власника (контролер даних, контакт, DPA з Google).

# Функціональні вимоги

Обовʼязкове застереження: результат потрібно додатково перевірити; це не юридична й не медична порада.

Форма:
1. Обовʼязкові (required) активні інгредієнти — autocomplete + можливість ввести власний, якого немає в системі.
2. Опціональні (optional) інгредієнти — так само.
3. Країна відправлення (departure) — autocomplete.
4. Країни призначення (destination) — до 10; після заповнення першої обовʼязкової зʼявляється поле для наступної.
5. Submit — активний лише при ≥1 required-інгредієнті, departure і ≥1 destination.

Таблиця (після Submit), поля: назва інгредієнта + required/optional; країна; статус + колір (дозволено / за рецептом / заборонено); посилання на джерело; Google-пошук «доступний»; Google-пошук «потрібен рецепт»; Google-пошук «заборонений»; ChatGPT-посилання із заготовленим промптом (доступний / за рецептом / заборонений).
Сортування: країна → її інгредієнти → наступна країна.

Висновки (списки країн): (1) усі інгредієнти дозволені; (2) усі required дозволені; (3) хоча б один інгредієнт за рецептом; (4) хоча б один required за рецептом; (5) хоча б один optional за рецептом.
Рекомендації: інші країни з класифікатора, де (1) усі інгредієнти дозволені; (2) усі required дозволені.
Додатково: альтернативи інгредієнта; назви різними мовами у форматі «Назва англійською (назва мовою користувача)».

# Модель даних

- **Список країн**: назва (EN/UK) + alpha-3.
- **Список джерел**: масив alpha-3 країн, URL, список активних інгредієнтів з інформацією «дозволений?» і «потрібен рецепт?».
- Після **Submit** з джерел і вибраних країн будується **карта «країна × інгредієнт → статус + джерела»**; це єдине джерело істини для таблиці, висновків і рекомендацій (рекомендації рахуються по всіх країнах класифікатора).
- У плані: схема JSON і валідація в CI; чиста функція побудови карти з unit-тестами; правила конфліктів джерел і перевизначення групового джерела записом країни; статус **unknown** (відсутність даних ≠ «дозволено»); нормалізація назв і синоніми EN/UK; custom-інгредієнти → unknown + лише Google/ChatGPT-посилання.
- Не вигадуй правових фактів. Запропонуй початкові джерела (INCB, WHO, МОЗ/митниці/посольства, національні переліки контрольованих речовин) і ліцензійні нюанси, реалістичний MVP, `verifiedAt` для кожного джерела, процес правок від спільноти (issue/PR-шаблон «report incorrect data»).

# Теми, які обовʼязково обговори зі мною

1. **Транзит**: окреме поле «пересадки», позначка «транзит» у спільному списку, чи лише destination. Ліміт 10 і різні правила транзиту.
2. **Статуси**: чи потрібні unknown, restricted (дозвіл/сертифікат/ліміт), controlled; секція висновків «Недостатньо даних».
3. **Конфлікти джерел**: найсуворіший / найсвіжіший / за пріоритетом; показ усіх джерел; попередження про застарілі дані.
4. **Обмеження**: кількість/дозування/форма, довідка чи переклад рецепта, митна декларація, громадянство — MVP чи пізніше.
5. **Інгредієнти**: джерело назв і синонімів (INN/ATC), торгові назви → діюча речовина.
6. **Departure**: лише контекст чи окремі правила вивезення.
7. **UX**: мобільна таблиця (картки / скрол із закріпленою колонкою / акордеон), шеринг через URL-стан, друк/PDF, «copy summary», скидання форми, збереження останнього запиту, обробка дублів і помилок.
8. **Посилання**: мова шаблонів Google/ChatGPT, точні формулювання.
9. **Якість**: unit-тести (Node у Docker), перевірка живості URL джерел, Lighthouse/axe у CI, поріг блокування деплою.
10. **Офлайн/PWA** і оновлення даних (вручну чи GitHub Action за розкладом).
11. **Бренд**: логотип, палітра, шрифти (системні vs веб), тон, іконки статусів; масштаб країн (усі ~250 чи підмножина).
12. **Правове**: сторінка Disclaimer/Terms, формулювання про заборонені речовини без заохочення порушень, ліцензія коду й даних, CONTRIBUTING, README, монетизація (впливає на privacy і довіру).
